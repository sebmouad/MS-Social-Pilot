# Workspace data controls

Settings > Data requests durable background ZIP exports rather than keeping an HTTP request open while building. Only current active workspace owners/admins with Settings Data access can request, list or download. Download checks authority again after disk I/O, tenant scope and expiry; responses use no-store. English/French export copy uses the shared Button, Dialog and DataTable. The app defaults to English; the component also accepts French.

`modules/settings/server/exports.ts` reuses `exportWorkspaceArchive`; it does not implement a separate record inventory. The existing manifest discloses coverage/exclusions. Provider credentials and instance-wide authentication/audit records remain excluded. Existing archive size and workspace operation timeout settings bound the in-memory build. Background processing does not make this builder streaming or unlimited.

Jobs persist requested/running/ready/failed/expired states. Requests serialize per workspace and deduplicate unfinished jobs. Claims use atomic conditional writes, lease tokens and PostgreSQL row locks with SKIP LOCKED. Builders retain a row lock through file creation; failure and expiry cleanup acquire fenced row locks before removing files. Interrupted claims recover after their lease. Jobs expire from request time, including preparation. Root settings in Settings config: `data.exportMaxJobs`, `data.exportExpiryHours`, `data.exportWorkerBatch`, `data.exportLeaseSeconds`, `data.exportSchedule`. No central registry or schema-version edit is included.

ZIP files live under the captured canonical media root at `exports/<workspaceId>/<jobId>.zip`, created exclusively with mode 0600 and no-follow checks. Directory links are rejected. Expired jobs cannot download before cleanup. The worker cleans expired files even for suspended workspaces, backs off inaccessible storage, and limits each pass. Failed/expired history is retired on subsequent requests.

Erasure discovers the job table through its workspace foreign key. A deletion trigger preserves archive root/identity in `rebuild_export_file_cleanups` until disk cleanup completes. The outbox deliberately has no workspace FK so it survives erasure and restarts. `removeWorkspaceStorage` removes current workspace media/exports and earlier export roots recorded by the outbox, then clears it; the worker also drains individual orphan files. This handles configured media-root changes without editing the erasure index. Workspace identity/members remain; remote provider content is untouched.

HTTP: GET/POST `/api/settings/data/exports`, GET `/api/settings/data/exports/<id>`. POST requires same-origin and exact `REQUEST WORKSPACE EXPORT <workspaceId>`. Settings-owned MCP declares `list_workspace_exports`, `request_workspace_export`, `download_workspace_export`, and `msp://data/exports`. Request uses the same exact confirmation; resource-restricted credentials cannot access workspace archives. MCP downloads return base64 ZIP bytes; transport response ceilings can limit large archives, for which authenticated HTTP download is preferable.
