# Ads read model

The rebuild Ads routes read `AdAccount` and every stored `AdInsight` level (`account`, `campaign`, `adset`, `ad`) through workspace-scoped queries. URL filters are bounded to workspace account IDs and UTC calendar dates. The default window is the latest 30 calendar days.

Summaries add daily spend, impressions, clicks, and numeric action values. Reach, CPP, frequency, and arbitrary provider `fields` use the latest daily row because they are snapshots or provider-specific values. CPC, CPM, and CTR are calculated from the selected-period spend/click/impression totals. Each object has a collapsed daily-details disclosure with every stored day's CPC, CPM, CPP, CTR, frequency, action JSON, and provider `fields`; this preserves values that should not be summed.

Campaign creation is available to workspace owners and admins when the Root ads-management switch, selected platform switch, workspace feature entitlement, write permission, resource scope, connected selected ad account, and provider grants are all present. The account's platform module owns provider scopes, objective validation and exact confirmation. Creation starts paused; it does not launch delivery or create creatives or ads. Each request records an audit event without credentials. Existing status and budget edits use the same server-side boundary and confirmation pattern.

Managers can also create a paused ad set under a campaign present in that account's stored campaign insight history. The form requires a daily amount in the account currency, one two-letter country code, and a supported optimization goal; billing uses impressions and bidding uses lowest cost without cap. The provider reads the campaign's live `account_id` before submitting `POST /{ad-account-id}/adsets`. Workspace write authorization and the campaign/account relationship are checked before creation. Limited page-scope users cannot create ad sets because the current data model cannot prove a campaign-to-Page association. New ad sets stay paused; this path does not create creatives or ads, and a just-created campaign must first appear in synced insight history before it can be selected. If provider creation succeeds but the audit write fails, the action still returns the created ID with `auditRecorded: false`, and the UI warns against submitting again.

Both campaign and ad-set creation preserve confirmed remote success if the subsequent local audit write fails. Responses include `created: true`, the paused remote ID, `auditRecorded`, and a warning when audit persistence failed; structured fallback logs contain only operation/actor/workspace/object IDs. Clients must retain that receipt and avoid repeating creation. This does not solve ambiguous provider timeouts, concurrent duplicate creation, or durable idempotency; those reconciliation paths remain release gaps.
