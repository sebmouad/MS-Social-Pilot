# Workspace data controls

The Data and privacy settings page exports a JSON snapshot of workspace details, memberships, posts and destination links, connection metadata, inbox history, and stored Page and ad metrics. It omits provider access and refresh tokens and the instance-wide `root_activities` audit history. The export is generated on request, sent with `no-store`, and is not persisted by the app.

Deleting workspace data requires an owner or admin and the exact confirmation `DELETE`. Before confirmation, the page requests counts for mapped records and every additional table with a direct foreign key to `workspaces`. The delete runs in one transaction: it locks the workspace row, enumerates those tables from PostgreSQL's catalog, removes their rows, and relies on verified cascading foreign keys for dependent records. Workspace identity and memberships remain. The timeout is managed by Root. The audit event with aggregate record counts is written in the same transaction. A rollback-only rehearsal in the isolated legacy schema verified that synthetic label and media records were removed inside the transaction while membership remained, then restored by rollback.

The JSON export remains limited by the rebuild's partial Prisma compatibility view and does not yet include all legacy feature records or media bytes. Database deletion refuses workspaces that still have `media` or `workspace_exports` rows, because those records can refer to files under `MEDIA_DIR/<workspaceId>` and `MEDIA_DIR/exports/<workspaceId>`. A crash-safe, symlink-safe file cleanup queue and complete export are still required before this becomes full erasure. Orphaned files without database records, external provider content, and installation-wide audit details are not removed by this path. Do not describe the current JSON export as a full backup.

Disconnecting a social source offers two local choices. Retaining history disables its channels and ad accounts while keeping records. Delete mode first previews counts for mapped channels, ad accounts, insights, inbox messages and comments, destination links, and posts that will become orphaned. It removes those mapped records; a post with links to other channels remains. The preview is an estimate and does not count cascaded rows in unmapped legacy tables. Delete mode is blocked while posts remain scheduled at the provider. Neither choice removes remote posts or revokes authorization at the provider. The choice and actual affected counts are audited.
