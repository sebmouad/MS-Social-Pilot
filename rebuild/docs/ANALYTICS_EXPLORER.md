# Analytics Explorer

`/analytics/explorer` provides a focused catalogue view over the stored metrics already readable by Analytics. It filters by the active authorized channel and ad-account selection, inclusive UTC date range, metric name/source, and measurement kind. Selecting a metric opens its complete bounded stored date series and resource/dimension rows; source provenance, aggregation semantics, and coverage remain visible. Missing values are explicitly unknown, not zero.

The page and `GET /api/analytics/explorer` call `readAnalyticsExplorer` from `modules/analytics/server/explorer.ts`, which delegates tenant, entitlement, date, resource, and provider authorization to the shared Analytics reader. Explorer-specific source and kind filters are applied to those returned metrics. The read-only MCP host integration exports `analyticsExplorerToolDefinitions`, `analyticsExplorerTools`, `analyticsExplorerWriteTools`, and `executeAnalyticsExplorerTool` from `modules/analytics/explorer-mcp.ts`; the host must map `get_analytics_explorer` to `analytics/overview` and apply its normal current feature permission filter.

The Root-owned defaults are exported as `ANALYTICS_EXPLORER_CONFIG` from `modules/analytics/explorer-config.ts`. Host integration must add this tuple to the central registry and advance its schema version. Explorer uses the lower of its own search bound and the shared Analytics search bound. Metric list and detail tables use the existing Analytics page/detail limits. The MCP executor accepts an optional positive result cap and clamps both pages to it; list metadata omits the full series and resource arrays.

CSV remains the existing `analytics/reports` export. The page exposes its link only when the current viewer has both export entitlement and permission. It removes explorer-only filters and pagination before calling the existing export route, so no new export implementation or provider request is introduced. Explorer reads stored data only; it does not start background synchronization.
