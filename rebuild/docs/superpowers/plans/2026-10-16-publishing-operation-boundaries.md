# Publishing operation boundaries

Goal: prevent cancellation/edit/deletion races with publication and recheck current authority inside the service. Preserve edit/delete forms on failed or unconfirmed results. Required architecture: ARCHITECTURE_CONTRACT.md sections 3–10; existing design/UX contracts.

- Product-owned access and operation guard: active identity, membership, entitlements, feature write and intersected channel scope. One workspace lock; post lock before target lookup; deterministic destination locks shared with disconnection. Refresh authority after locks. Root controls operation/local-transaction budgets and identifier/resource bounds.
- Lifecycle owns its guard. UI/MCP/worker wrappers skip their generic workspace lock for these operations. A stale worker candidate must match its original scheduled timestamp and state before publishing; manual publishing remains explicit. Processing claims block local deletion until outcomes can be reconciled.
- Local writes and audits share bounded transactions; aborted operations cannot begin subsequent writes. Provider requests receive a whole-operation signal combined with their configured per-request deadline. Persisted processing claims remain evidence after unknown results; cancellation does not prove a remote side effect never occurred.
- Stateful edit/delete actions preserve user values, dialog and checkbox choice on failure, disable repeats while pending, and redirect only after successful service return. Keep shared dialogs/theme controls.
- Tests: authorization and guard cases, deterministic independent-client PostgreSQL publish/cancel/edit/delete races, stale worker schedule, provider cancellation, actual local UI/API/MCP examples with cleanup. Full suite/typecheck/isolated build and independent review before commit/push.

No new schema or production change is intended. Durable first-comment/publishing/deletion recovery, additional formats, real Facebook verification and full parity remain subsequent required batches, not waived requirements.

Outcome: implemented and locally verified. Final suite 994 tests/171 files (16 PostgreSQL tests/12 integration files), typecheck and isolated build pass. Actual localhost MCP authorization/mutation probe and browser failure/success paths pass with fixture cleanup. Browser success exposed swallowed redirect control flow; fixed and regression-tested before publication. Independent lower-cost review found no additional introduced issue and retained uncertain-publication/deletion recovery as release blockers. See PUBLISHING_OPERATIONS.md and PREVIEW_QA.md for exact scope and remaining gaps.
