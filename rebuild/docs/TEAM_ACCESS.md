# Workspace team access — batch 61

Team membership belongs to the Settings product module. Its domain service is shared by the customer page, `/api/settings/team`, and workspace MCP. Every read/write checks the current active user, workspace membership, team feature, permission, entitlement and manager role. Writes repeat these checks inside the workspace operation and a serialized transaction, validate every channel against the same workspace and current platform access, and atomically commit membership/grants with a content-free domain audit. Disabled accounts cannot be added or edited; removing a disabled member is allowed and retains their other workspace memberships. Owners and admins always receive all-channel access; only an owner may assign or manage an owner role. Self-removal and demoting the final active owner are refused.

The directory is tenant-scoped and bounded by Root-managed member/channel limits. The UI lists available assignable channels and identifies unavailable existing grants. Editing preserves unavailable grants until the manager explicitly removes them; a warning explains the effect before saving. Component tests cover this recovery path. Member addition requires an existing active account. Add, update and remove each require an exact confirmation shared across UI and MCP. MCP exposes `list_workspace_team`, `add_workspace_member`, `update_workspace_member`, `remove_workspace_member`, and `msp://settings/team`; member and target output pages are bounded and continue with separate offsets.

Registry version 56 adds six active Settings controls: default role `contributor`, default all-channels access `false`, maximum members `500`, maximum channel grants `1000`, transaction timeout `15000` ms, and transaction max wait `2000` ms. These are validation/operation bounds and default values; they do not establish invitations, email delivery, onboarding, seat-plan policy, or billing behavior. Invitations and account lifecycle remain parity gaps. This batch adds no migration or provider operation; production remains on the legacy application.
